# The Wandering Earth v1.1.0

**Working planetary engines, real state, flame, rotation, self-loading fuel, and
Create Ponder tutorials.** Textures are now 32×32 with layered detail.

Mod jar: `wandering_earth-1.1.0.jar`
SHA-256: `ad457c58ec6f1dff5e59304a57d5bcbb69e97a3a236f2cfe19121348353bf334`

## What changed since 1.0.1

### 1. Engines are now machines, not decoration

Ten blocks moved from "static block with a chat line" to a real engine family
with a `BlockEntity`, blockstate state and tickers:

`planetary_engine_core`, `planetary_engine_nozzle`, `plasma_beam_emitter`,
`engine_light_pillar`, `equatorial_turning_engine`, `thrust_engine`,
`heavy_fusion_reactor`, `stone_burner`, `lighter_socket`, `ignition_core`

New classes:

| Class | Role |
|---|---|
| `com.wanderingearth.block.EngineBlock` | `extends Block implements EntityBlock`; owns `facing` + `lit` state, placement rotation, sneak-rotate, fuel insertion, flame particles |
| `com.wanderingearth.block.ModEngineBlockEntity` | persists `Fuel` / `BurnTimer` in NBT, burns one lighter stone per 40 ticks, absorbs dropped lighter stones every second |
| `com.wanderingearth.registry.ModBlockEntities` | `DeferredRegister<BlockEntityType<?>>` with `BlockEntityType.Builder.of(...).build(null)` |
| `com.wanderingearth.compat.WanderingEarthPonder` | the three Ponder scenes, loaded reflectively |

### 2. Turns

`facing` (4 horizontal directions) is set from the player's look direction on
placement. **Sneak + empty-hand right-click** rotates the nozzle a quarter turn;
the blockstate `y` rotation and the `_front` face texture follow the value, and
the turn is confirmed in the action bar.

### 3. Spouts flame

`Block.animateTick` emits `ParticleTypes.FLAME` (two streaks) plus
`LARGE_SMOKE`, pushed along `facing` with slight upward drift, and a low
`SoundEvents.FIRE_AMBIENT` every sixth tick. Only while `lit=true`.
`lit=true` also swaps the model to `*_front_lit`, whose front face is drawn as a
glowing nozzle throat.

### 4. Loads lighter stones by itself

- **Manual:** right-click with a Lighter Stone (`useItemOn`) inserts one, lights
  the engine, plays `FIRECHARGE_USE`.
- **Automatic:** every 20 ticks the block entity scans a 3-block box for dropped
  `ItemEntity` stacks of `lighter_stone` and pulls them in, up to `MAX_FUEL = 64`.

### 5. Create Ponder ("hold W")

With Create installed, three scenes register through `PonderIndex.addPlugin`:
`planetary_engine`, `lighter_socket`, `moss_mainframe`. Language keys follow the
`<modid>.ponder.<scene>.header` / `.text_N` convention that Create uses.

Each scene is backed by a real structure file —
`assets/wandering_earth/ponder/<scene>.nbt`, a 5×5 stone-brick platform with the
machine in the middle — generated by `tools/gen_ponder_schematics.py` (a plain
gzipped-NBT writer, no external libraries). The engine scene animates
`showSection` / `cycleBlockProperty(LIT)` / `emitParticles(FLAME)` / `hideSection`.

The whole integration stays off the classpath when Create is absent:
`WanderingEarth#clientSetup` checks `ModList.get().isLoaded("create")` and only
then loads `com.wanderingearth.compat.WanderingEarthPonder` by name.

### 6. Textures

All block and item textures regenerated at **32×32** (was 16×16) with:

- directional lighting per pixel, bevels, radial bolts and panel seams
- rust mottling and scratches, brass concentric rings, cable highlight lines
- CRT scanlines and text runs on screens, three-layer MOSS red dot
- radial bloom on glow blocks, crack networks on ice/glass
- dedicated art for the engine faces: rings + bolts (`_top`), coolant pipes
  (`_side`), a bolted nozzle throat (`_front` / `_front_lit`)
- real silhouettes for equipment items (dome + visor, torso + buckle,
  rifle receiver, cog teeth, shield chevron) instead of a placeholder box

## Correctness work

The offline build compiles against hand-written `net.minecraft.*` signature
stubs, so the build also ships a linkage verifier that catches what javac cannot.

- `tools/verify_jar.py` checks **invoke kind** (ICCE), **member linkage**
  (NoSuchMethod/FieldError, including inherited members), **field staticness**,
  **override descriptors** and **stub leaks**. Current jar:
  `invoke sites: 279 | member refs: 319 | fields: 40 | overrides: 10 | PROBLEMS: 0`.
- One real bug was found this way and fixed: `BlockState.setValue` was declared
  directly on `BlockState`, but in vanilla it lives on `StateHolder` where its
  generic return type erases to `java.lang.Object`. The stub now models the real
  `StateHolder<O, S>` hierarchy, so javac emits the same descriptor as vanilla.
- Regression-tested: when the verifier is pointed at a deliberately broken jar
  (MutableComponent declared as an interface) it reports the exact ICCE site that
  crashed in v1.0.0, and exits non-zero.

## Building

`gradlew build` on a machine that can reach `maven.neoforged.net`; Ponder is
pulled from `maven.createmod.net` at `compileOnly` scope
(`net.createmod.ponder:ponder-neoforge:1.0.82+mc1.21.1`).

Offline, without that host: `tools/build_offline.py` (same sources, real NeoForge
API jars plus compile-time stubs) followed by `tools/verify_jar.py`.
